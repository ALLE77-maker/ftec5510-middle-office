# 业务规则与演示假设

## 本次实现的选择

- 独立 HTTP 服务，Python 3.10+ 标准库，默认 8200 端口。保留原 C++ 项目作为客户端接入对象。
- 每个模拟账户使用一种计价币，例如 USDT。BTC/USDT 和 USDC/USDT 共用该账户资金。不同计价币需创建相应账户或后续实现换汇。
- 每个金额和数量保留 8 位小数，Decimal 高精度计算，账本写入采用四舍六入五成双。成本包含买入费，卖出收益扣除卖出费。
- 产品风险档位由 `--product-risks` 的 JSON 文件配置。无配置时仅检查通用交易规则。产品档位属于小组演示配置。
- 风险阈值可以在创建虚构账户时指定，默认订单名义金额上限 100000、集中度 60%、浮亏 10%、AML 大额 10000、60 秒内 5 笔成交触发频率规则。金额以账户计价币计量。

## 三条核心流程

### BPMN 01

账户设置按账户独立保存。行情源由采集或推送事件更新。只比较相同完整交易对，至少两路新鲜报价时推荐一个模拟来源。缺源或过期报价被明确排除。价格提醒按用户配置的上下阈值触发。

### BPMN 02

新请求创建唯一订单，依次检查格式、有效报价、计价币、额度、余额或可卖数量，以及配置了产品档位时的问卷限制。订单接受后固定来源及费用率。挂单预留资源，避免并发超买或超卖。

市价买单按 ask、卖单按 bid 模拟整笔成交。限价单只有买价不高于限价或卖价不低于限价时成交，否则等待后续行情。成交更新订单、现金、数量、成本和已实现盈亏，并生成唯一 Trade ID。更新整体放在同一 SQLite 事务中。重试同一 request_id 不生成第二笔成交。撤单仅适用于未成交订单并释放预留。

### BPMN 03

估值更新触发持仓集中度和浮亏检查，持仓市值以有效 last price 计算。报价不完整时显示 partial，完整账户总值和浮动盈亏设为 null，不把缺失估值填成零。

集中度为单个持仓市值除以账户总资产，包含账户现金。浮亏比例为该持仓亏损额除以剩余成本。持续命中不重复创建活跃告警，恢复后再命中可重新提醒。

成交触发 AML 大额和短时频率监测。告警含关联 Trade ID、规则、阈值及时间，人工可关闭或升级并留下理由。已有告警不会因为同一订单重试重复出现。

## 存储与并发

SQLite 中保存一个完整业务快照，写事务使用 BEGIN IMMEDIATE，账户、订单、持仓、成交及告警一起提交或一起回滚，进程重启保留状态。此方式适用于小组课程规模，数据量大时应拆分关系表并采用索引和增量查询。

快照按用户过滤，AI 的两个数组最多各 50 行，超出会标记 truncated。详细流水和审计接口使用分页。中控读取当前账本时间与行情采集时间分别保留。
